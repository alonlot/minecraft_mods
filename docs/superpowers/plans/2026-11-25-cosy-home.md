# Cosy Home, Food and Kitchen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a warm home layer to the mod: a warming hearth, bobbing candles, furniture, indoor sounds, wizard food,
a butterbeer keg, and a stove with a self-stirring pot.

**Architecture:** Two independent streams on two branches, each in its own worktree, merged afterwards into `cosy`:
- **Stream A (Home):** branch `cosy-home`, worktree `C:/Users/alonl/hp-cosy-home`. Tasks A1 to A4.
- **Stream B (Food + Kitchen):** branch `cosy-food`, worktree `C:/Users/alonl/hp-cosy-food`. Tasks B1 to B5.

Each stream puts its registrations in its own class, loaded the way `ModDecorations` is: a static `init()` called from
the `ExampleMod` constructor next to `ModDecorations.init()`, and a `CREATIVE_ORDER` list added to `MAIN_TAB`. Game
rules live in pure `*Rules` classes covered by JUnit, and world behaviour is covered by GameTests.

**Tech Stack:** Forge 51 (MC 1.21), Java 21, JUnit 5 (`src/test`), Forge GameTest (`runGameTestServer`), hand-written block
model JSON, 16x16 textures, and ElevenLabs sounds converted to mono OGG.

**Spec:** `docs/superpowers/specs/2026-11-25-cosy-home-design.md`. Read it first; its values are binding.

## Global Constraints

- Mod id `hogwartsmagic`. Use package `com.hogwartsmagic.cosy` for new code. Furniture goes in the existing
  `block/decor/ModDecorations.java`.
- It must be safe on a dedicated server. Renderers, screens and sound loops are client-only classes, referenced only
  from `event/ClientModEvents` or `@Mod.EventBusSubscriber(value = Dist.CLIENT)` classes. Gameplay is server-authoritative.
- Don't switch on an enum in render or model code; use if/else. Don't use entity-event bytes 21, 35 or 63; use 61, 62, 64, 66 or 67.
  Custom Screens call `renderTransparentBackground`, never `renderBackground`.
- 1.21 API: food via `new Item.Properties().food(new FoodProperties.Builder()...build())`. There's no `MobType`. `SavedData.save` is public.
- Every block needs a blockstate, a block model, an item model, a loot table (`data/hogwartsmagic/loot_table/blocks/`) and a
  lang entry. Every item needs an item model, a texture and a lang entry. Everything goes in the creative tab.
- Item textures are 16x16 hand-pixel grids. Write a script in `tools/item_textures/cosy.py`, following the style of
  `tools/item_textures/potions_materials.py`, and use the `texturing-minecraft-items` skill. Don't use Flow or AI images.
  Block textures are 16x16 PNGs from a script in `tools/cosy_textures/`.
- Sounds follow `C:\Users\alonl\.claude\projects\C--Users-alonl-OneDrive-Desktop-harry-potter-mod\memory\reference_elevenlabs_sfx.md`.
  Read the key from the local file named there and never commit it. Envelope-trim and level-match before converting
  to mono OGG. Register in `ModSounds` and `assets/hogwartsmagic/sounds.json`.
- Shared files touched by both streams are `ExampleMod.java` (two lines each), `ModSounds.java`, `sounds.json`, `en_us.json`
  and `ClientModEvents.java`. Only append, keep each stream's additions together in one block marked
  `// ---- Cosy home ----` or `// ---- Cosy food ----`, and don't reorder or reformat existing lines.
- Build only inside your own worktree. Never run gradle in `C:/Users/alonl/OneDrive/Desktop/harry potter mod`, which may
  have a client running.
- Commit after every task on your stream's branch, ending each commit message with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Don't push; the integrator pushes.

## Verification commands (per worktree)

- Unit tests: `./gradlew test --offline --tests 'com.hogwartsmagic.cosy.*'`. Expected: BUILD SUCCESSFUL.
- Compile: `./gradlew compileJava --offline`.
- GameTests: `./gradlew runGameTestServer --offline`. Expected: "All N required tests passed". Your new tests must pass.
  Note any old failures, but don't fix them.
- Data and registry check: `./gradlew runServer --offline` until "Done (", then `stop`. There must be no missing-model,
  recipe-parse or loot-table errors for cosy ids in `run/logs/latest.log`.

## Review Focus

1. **Old worlds with floating candles:** placed candles must load lit and keep working after `LIT` and the block entity
   are added. A2 has a GameTest that sets the plain default state and checks it is lit and has a block entity.
2. **A pot with no heat, or heat removed mid-cook:** progress must stop without being lost, and the ingredients must
   not vanish. B5 test `potKeepsProgressWhenHeatRemoved`.
3. **Breaking a block entity that still holds things,** such as a pot with ingredients or a keg with servings:
   ingredients drop, and servings are lost but nothing dupes. B4/B5 test `brokenPotDropsIngredients`.
4. **Using a frog box with a full inventory:** the card is dropped at the player's feet, not lost. B2 test
   `frogCardDropsWhenInventoryFull`.
5. **Dedicated server:** the `runServer` check must show no client class loaded. A4 and B2 put their client code only
   in client-only classes, and the data check proves it.
